# Same-origin API gateway and origin protection

The browser must be able to see its own requests and downloaded JavaScript. DevTools cannot be securely disabled. API names and a user's own requests are not secrets. JWT validation, ownership checks and a server-only origin guard prevent unauthorized access even if somebody knows an endpoint.

## Implementation

- Production Angular uses relative `/api` URLs instead of an embedded backend hostname.
- Vercel rewrites `/api/:path*` to the Node gateway. SPA routes continue to use `index.html`.
- The gateway forwards only to its configured HTTPS origin under `/api/`. It passes user Authorization headers and a separate server-only `X-Omnispace-Proxy` secret. It overwrites any client-supplied proxy secret.
- Responses are streamed, are not cached, and do not forward backend redirects or arbitrary response headers. Missing gateway configuration fails closed with 503.
- OriginProxyFilter can require the server-only secret before API requests reach Spring Security. That secret does **not** grant a user identity or bypass existing JWT/ownership checks.
- The optional Caddy template additionally rejects unmatched origin requests, including the origin homepage. Bind the backend's published port to loopback so callers cannot bypass Caddy through port 8080.
- Login/register requests do not send an existing bearer token. An old request's 401 cannot clear a newer login. Current invalid sessions still sign out. Expected authentication failures do not log stack traces or token details.
- Spring error dispatch preserves application statuses; clients receive controlled authentication JSON and no exception/stack trace details. Wrong credentials still legitimately return 401.

## Required deployment order

Do not enable origin restrictions before the gateway is live, or the existing frontend will be blocked.

1. Generate a random secret of at least 32 characters. Store it only in private deployment environments; never Angular source or a committed config. Do not print it in terminal logs.
2. In the Vercel frontend project, set server-side environment variables:
   - `OMNISPACE_API_ORIGIN`: the existing HTTPS API origin, without `/api` or a trailing path.
   - `OMNISPACE_PROXY_SECRET`: the generated secret.
3. Deploy the updated frontend **and** `api/gateway.mjs`. Confirm the Vercel project root is `omnispace/frontend`, so native Node functions are included alongside the Angular static output.
4. Verify the website's `/api/properties`, real login, listing pictures and private design read/write through the gateway. Test within the actual hosting platform: unit tests cannot prove Vercel rewrite behavior.
5. Deploy the updated backend with `ORIGIN_PROXY_REQUIRED=true` and the same `OMNISPACE_PROXY_SECRET`. Pass both explicitly into the backend container. It refuses to start with a missing/short required secret. The default remains false for local development and safe staged rollout.
6. Optionally replace the Caddy site using `Caddyfile.origin-guard`, supplying `API_DOMAIN` and the same `OMNISPACE_PROXY_SECRET` to the Caddy container. Validate before reload. The header must reach the backend for its independent check.
7. Keep backend publishing limited to `127.0.0.1:8080:8080` (or no published port if administrative loopback access is unnecessary); Caddy reaches it on the internal Docker network. Preserve private MongoDB access and existing volumes.
8. Verify direct public-origin requests return 404 without the secret, while same-origin gateway requests still work and private routes still require JWT/ownership.

Rollback: restore the prior Caddy config and disable `ORIGIN_PROXY_REQUIRED` before restoring an older direct-to-origin frontend. Never publish the shared secret in client code to resolve a connectivity problem.

## Hosting constraints

The gateway limits request bodies to 4.4 MB, below Vercel's documented function body limit. Large inline-photo records may need fewer/smaller photos or a later authenticated object-storage upload flow. There is no silent image truncation. Outbound requests time out after 30 seconds. The proxy does not support WebSocket upgrades; the current HTTP API remains supported.

## Verification

```powershell
cd omnispace/frontend
node --test tools/gateway.test.mjs
npm test -- --watch=false
npm run build -- --configuration production
```

Run Maven `verify` in `omnispace/backend` as well. Tests include path traversal/SSRF boundaries, spoofed headers, secret redaction, 401 propagation, upload limits, session races, origin-required wiring and private API access.

Live checks on 21 November 2026 found that the existing public listing endpoint already returned 200; private designs and `/api/auth/me` returned 401 without authentication. The screenshot's historical 401 messages are not proof that private data can be read. Browser tracking-prevention and lazy-image messages are generated by the browser and cannot be reliably suppressed by application code. The Three.js deprecated shadow-map setting has been replaced with PCFShadowMap.
